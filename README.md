# あいぼう手帳

**話すだけで記録が残り、相棒が育つ健康記録アプリ。**
運動・食事・睡眠・体調・メモを、スマホから数秒で記録できます。
話しかけるだけで種類・時刻・内容を自動で振り分け、カロリーも見積もります。
記録を続けると相棒（キャラクター）のレベルが上がり、姿が変わっていきます。

## このリポジトリについて

個人用の `life-log` リポジトリから、**製品として App Store に出すため**に
ライフログ機能だけを切り出したものです（やることハブ・投資・TOEIC・
しごとノートなどの個人用アプリは含みません）。

いまの構成は「利用者が自分の Notion に記録する」形（自分のサーバーにデプロイして使う）です。
App Store で「入れたら動く」を実現するために、次の順で作り替えていきます。

| 段階 | 内容 | 状態 |
|---|---|---|
| Step 0 | ライフログ機能の切り出し・名前の変更 | ✅ 完了（このリポジトリ） |
| Step 1 | メールでログイン（Supabase Auth）、自前DB（Postgres）への保存、アカウント削除、利用者ごとのAI利用枠、Stripe決済 | 🔄 進行中（ログイン・自前DB・アカウント削除・AI利用枠まで実装済み。Stripeは未） |
| Step 2 | Capacitor でネイティブ化、HealthKit連携、プッシュ通知、TestFlight | 未着手 |
| Step 3 | プライバシーポリシー・利用規約・免責、審査、公開 | 未着手 |

価格モデルは「無料 ＋ プレミアム ¥300/月（年払い ¥3,000）」の予定。無料でも手入力の記録・履歴・相棒は使え、
音声入力（月20回）・ふりかえり（週3回）だけ回数に上限を置く。App Store 版はWeb版の反応を見てから判断する。

### Web版（自前DBモード）の動かし方

**NotionもObsidianも使っていない人（家族・友人など）にそのまま使ってもらう**ためのモード。
利用者はURLを開いてメールアドレスを入れるだけで始められる。
Supabase（ログイン＋Postgres）とRenderの用意から、使う人への案内文までを
**[docs/SETUP-web.md](docs/SETUP-web.md)** にまとめてある。

仕組み：`.env` に `STORAGE=pg`・`DATABASE_URL`・`SUPABASE_URL`・`SUPABASE_ANON_KEY`・
`SUPABASE_JWT_SECRET`（または `SUPABASE_JWKS_URL`）を設定して起動すると、
記録は Postgres に保存され、`/api` はログイン必須になる。ログインは `login.html`
（メールのマジックリンク）。未設定なら従来どおり「利用者のNotion」に保存するモードで動く。
テストは `DATABASE_URL` があれば自前DBのぶんも流れる（無ければ飛ばす）。


## 構成（v2：クラウド対応）

PCの電源に関係なく使えるように、常時起動のクラウド版をRenderにデプロイしています。

| | クラウド版（常時稼働） | ローカル版（PCで起動時のみ） |
|---|---|---|
| URL | https://<あなたのRenderのURL> | `start.bat` で起動、`http://<PCのIPアドレス>:3800` |
| Notion | ✅ リアルタイムで反映 | ✅ リアルタイムで反映 |
| Obsidian | ❌ 直接は書き込めない（ローカルファイルのため） | ✅ リアルタイムで反映 |

**つまり：外出先やPCの電源が切れている時にクラウド版で記録したものは、
Notionにはすぐ反映されますが、Obsidianへの反映はPCが次に起動した時になります。**
PC起動時（ログイン時）に `sync.js` が自動実行され、Notion上にあって
Obsidianにまだ無い記録を追いつかせます（Windowsのスタートアップフォルダに登録済み）。

## 使い方（入力）

- 常にどこからでも：https://<あなたのRenderのURL> を開いて入力
- 自宅WiFi内 かつ PC起動中なら：`start.bat` を実行してローカル版を使うと、Obsidianにも即座に反映されます

トップ画面で「運動／食事／睡眠／体調」のタブを選び、簡単な項目を入力して
「記録する」を押すだけです。同じ日に何度入力しても、その日のブロックに
追記されていきます。

**話しかけて記録することもできます。**「記録する」の右にある小さな青い
マイクのボタンを押して話すと、カテゴリ（メモ／運動／食事／睡眠／体調）も
項目も自動で選ばれて入力欄が埋まります。内容を確認して「記録する」を押せば
完了です。入力欄ごとに付いている灰色のマイクは、その欄に文字起こしを入れる
だけのボタンです。
マイクの許可を聞かれるのは**アプリを開いてから最初の1回だけ**です
（一度もらったマイクは持ったまま使い回し、録音していない間は音を拾わない
ようにしています。アプリを離れた時はマイクを手放します）。

**ホーム画面に追加するとアプリとして使えます（PWA）。** オフラインでも
アプリ自体は開き、最後に見た記録がそのまま表示されます（Service Workerが
ネットワーク優先＋キャッシュフォールバックで配信）。iOS用のアイコンも
PNGで用意しています。プッシュ通知（記録リマインド）は、通知サーバー
（VAPID鍵と購読情報の保存先）が必要になるため未対応です。

**送信に失敗しても記録は消えません。** 通信エラーやサーバーの一時的な失敗
（Render無料プランのスリープ明けなど）の時は、記録を端末に保存して
「未送信の記録が◯件あります」と表示し、接続が戻り次第自動で送り直します
（開いた時・回線復帰時・1分おきに再試行）。日をまたいで送られた記録も、
入力した日のブロックに正しく入ります。内容の不備による失敗（4xx）は
再送しても直らないため貯めません。

カテゴリは上のタブを押すほか、**タブの帯か入力フォームの上を左右に払う**
（スワイプする）ことでも切り替えられます。左に払えば次、右に払えば前です。
縦スクロールや入力の操作を邪魔しないよう、指を離した時にだけ判定します。
横に44px以上・縦の1.2倍以上動いた時に切り替わります。入力欄やボタンの上から
始めたスワイプも効きます（例外は「いま編集中の文字入力欄」だけ。文字の選択や
カーソル移動と衝突するため）。
PCでは矢印キーでも移動できます（入力欄にカーソルがある時を除く）。

時刻は「時」「分（5分刻み）」をタップして選びます。メニューは**いつも画面の
中央**に開きます。iOSの標準selectのメニューは開く位置をWeb側から制御できない
（要素を中央に固定しても、メニュー自体はiOS側の都合で画面上部に寄ってしまう）
ため、見た目と操作感を標準メニューに寄せた自前のリスト（タップで即確定・
チェックマーク付き）を中央に出しています。就寝時刻だけは0時ではなく24時も
選べます（日本では「24時に寝た」と言うため）。

アプリのマスコットは、ドット絵のキャラクターです。既定は茶碗ごはんの
「ごはんくん」ですが、**12種類から選べて、名前も自由に付けられます**
（ごはんくん・おにぎりくん・ほのおくん・くもくん・もちくん・たまごくん・
パンくん・りんごちゃん・おちゃくん・プロテインくん・ダンベルくん・
ブロッコリーくん）。
キャラクターにはドット絵風の縁取りが付いていて、背景と同系色のキャラ
（黒地のダンベルくん、白地のもちくん等）でも輪郭が沈みません（縁の色は
テーマに合わせて変わります）。
キャラクターにはそれぞれ**性格（難易度と口調）**があります。難易度は
**経験値の倍率**（やさしい★〜鬼★★★★★）で、きびしい相棒ほど鍛え方がうまい
という設定です。難易度が高いほど、同じ記録でもレベルが**上がりやすく**なります
（ダンベルくん★5がいちばん上がりやすい）。口調は「今日の活動」の
厳しさの既定値になります（口調設定が「キャラにおまかせ」の時。手動で選べば
そちらが優先）。各キャラの性格は着せ替え画面に表示されます。
変更は、右上の⚙️ →「キャラクター設定」から。選択はこの端末に保存されます。
⚙️は「設定」メニューになっていて、Notion連携と天気の地域はその中の一項目です。
一番上で**下に引っぱると再読み込み**できます。ヘッダーのすぐ下に帯が出て、
「引っぱって更新」→「離して更新」→「更新中…」→「更新しました」と変わるので、
どこまで引っぱれば更新されるか・いま何をしているかが分かります。
設定・キャラクター設定・編集などの下から出るシートは、**下にスワイプしても
閉じられます**（シートが最上部までスクロールされている時に下へ引っぱる。
途中で離すと元の位置に戻ります）。
画面の**テーマ（ブラック/ホワイト）**も設定メニューで切り替えられます。
⚙️ →「からだの設定」では、性別・年齢・身長・体重・ふだんの活動量を入れられます。
1日の目安カロリー（記録の合計カロリーの横に出ます）とBMIの計算だけに使い、
入力した値はこの端末にだけ保存されます。
カレンダーは⚙️ →「カレンダー」から開けます（トップ画面には常には出しません）。
開くと、**見出しの両側の ‹ › ボタン**と、**左右に払う**操作のどちらでも前の月・
次の月に変わります（右へ払えば前の月、左へ払えば次の月。1年前から来月まで。
端まで来るとボタンが薄くなって押せなくなります）。記録のある日には点が付き、
日付を押すとその日の記録へ飛びます。
カレンダーがあった場所には、代わりに**ポイントの推移**（直近14日の折れ線チャート）
が出ます。指でなぞる（PCならマウスを乗せる）と、一番近い日にスナップして
その日の点数を確認できます。
トップ画面に出す項目は、⚙️ →「ホーム画面の表示」で**ON/OFFスイッチで
選べます**（時計と天気・今日の格言・今日の活動・ポイントの推移・今日の運動・
音声で記録・これまでの記録）。OFFにした項目はすぐに隠れ、選択はこの端末に
保存されます。記録フォームはこのアプリの中心なので常に表示されます。
キャラクターは**一緒に健康習慣に取り組む相棒（コーチングのパートナー）**という
設定です。「今日の活動」のコメントもその相棒からの**励まし**で、どの口調でも
叱りません。まず今日できたことを認めて、残りの時間を「一緒にやろう」の目線で
後押しします（超スパルタでも「ここからが本番だ、一緒に上げていくぞ！」のような
檄＝励ましであって、説教にはなりません）。**口調は選んだキャラクターの性格に従います**
（もちくん=超やさしい、ダンベルくん=超スパルタ等）。キャラクターを替えると、
表示中のふりかえりもその場で新しい口調で書き直されます。どの口調でも、
人格否定や健康を害するような物言いはしないように歯止めを入れています。
既定はブラックで、選択はこの端末に保存され、トップ画面と履歴画面の両方に効きます。

**相棒の詳しい様子は、ヘッダーの📊ボタンから「ステータス」画面で見られます。**
今の姿（レベルの飾り付き）・名前・レベル・次のレベルまでの進み具合のバー、
相棒の性格（難易度＝経験値の倍率と口調）、**今日もらったポイントの内訳**
（睡眠・運動・食事・体調・メモ・パーフェクトデーが何ptずつ入ったか）、
これまでの積み上げ（累計pt・連続で記録した日数・記録した日数・今月の記録・
今週の運動・運動5日を達成した週の数）、姿の変化の解放状況（Lv3/5/7/9）、
ポイントの決まり一覧が並びます。この画面からも相棒の着せ替えができ、
難易度が変わるとレベル表示もその場で変わります。

以下、既定のごはんくんを例に説明します。
トップ画面のヘッダー・アプリアイコン・「今日の活動」の顔がごはんくんで、
記録が完了すると、ボタンが黄色になって金色のキラキラが舞い、マスコットが
ぴょこんと跳ねてお祝いしてくれます（その後ふわっと元のボタンに戻ります）。
同時に、ヘッダーのキャラクター本人もカテゴリに合わせて反応します
（食事=もぐもぐ / 運動=スクワット3回 / 睡眠=うとうと💤 / 体調=うなずき /
メモ=ばんざいジャンプ。小さなハートも舞います）。
その後、**画面中央にキャラクターがでっかく登場**して、緑のオーラをまとって
ぐんっと成長します（ヘッダーのキャラ本人もひとまわり大きくなって戻ります）。
その記録でポイントを獲得した時は「+2pt」のように頭の上に浮かびます。
**レベルが上がった時は、成長の演出の代わりに専用のお祝い**が出ます。
ヘッダーで金色のリングときらきらが弾けたあと、画面全体が金色に光り、
足元から衝撃波が3重に走り、キャラクターが画面いっぱいに現れて2回跳ねます。
「LEVEL UP!」の文字と「Lv.4 ▶ Lv.5」（新しいレベルは少し遅れて大きく出ます）、
獲得ポイント、金色の紙吹雪が一緒に舞います。
ヘッダーやふりかえりのごはんくんをタップすると、ジャンプ・回転・ぷるぷる等
12パターンの動きからランダムに1つ遊びます（連続で同じ動きにはなりません）。
タップすると**ピコッと音が鳴ります**（音のファイルは持たず、Web Audioでその場で
作っているのでドット絵に合うピコピコ音になります。発射の芸だけは、ためのあとに
高いところへ駆け上がる専用の音です）。
音が鳴るのはタップの時だけでなく、**記録できた時（ピロン♪）・キャラクターが
成長する時（ぽわん）・レベルが上がった時（ファンファーレ）**にも、それぞれの
演出に合わせて鳴ります。レベルアップのファンファーレだけは、前触れの3連符から
駆け上がって和音で伸ばし、最後に上でキラッと鳴る4段構えの専用の音です。
まとめて⚙️ →「効果音」でOFFにできます。
**iPhoneは本体スイッチがマナーモードだと鳴りません**（Web側から音の種類を
指定する手段が無いためで、これはWebアプリ共通の制限です）。
11番目はその場でおおきくなってから戻る動き、12番目は**怒って発射する**動きで、
💢を出してぷるぷる震えたあと、身体ごと飛び出して画面の端で跳ね返りながら
飛び回り、元の位置に帰ってきます（飛んでいる間は画面の操作を邪魔しません）。

### 1日のトータルスコア

**その日どれだけ記録できたかを、100点満点のスコアで出します。**
「今日の活動」の見出しの右と、「これまでの記録」の日付ごとの右に並びます。
点数は下の育成ポイントと同じ計算（睡眠・運動・食事・体調・メモ・パーフェクトデー）で、
相棒の難易度には左右されません（難易度はレベルの上がりやすさにだけ効きます）。

点数に応じて色と言葉が変わります。色づかいは睡眠グラフ・今日の運動リングと
同じで、アプリの中で同じ色が同じ意味になるようにそろえています。

| 点数 | 言葉 | 色 |
|---|---|---|
| 0点 | （なし） | グレー |
| 1〜29点 | NICE | 青 |
| 30〜54点 | GOOD | 水色 |
| 55〜84点 | GREAT!! | 緑 |
| 85点〜 | EXCELLENT!! | 黄色 |

めやすとして、睡眠7時間＋運動1件＋3食＋体調＋メモがそろった日で90点です。

### ごはんくんの育成

ごはんくんはヘッダーの中を自由に動き回っていて、健康的な生活をすると育ちます。
歩くだけでなく、**ふわりと宙に浮いてただよったり、勢いよく飛んだり**します
（歩く・止まる・浮く・飛ぶを気まぐれに切り替えます。浮いている時はゆっくり
上下にゆれ、飛んでいる時は進む向きへ傾きます）。タップして芸をする時は
いったん地上に降りてから見せます。眠い時（記録が2日以上途切れた時）は
飛ばず、地上でゆっくり過ごします。
直近1年の記録からポイントを毎回計算し直す方式で、どこにも保存しません。
端末が変わっても同じ結果になり、長く続けるほどレベルが積み上がります。
サボると1年の窓から古い実績が抜けていくので、維持の動機にもなります。
（サーバー側がNotionの読み込みを60秒キャッシュして全画面で共有しているため、
1年ぶんの計算でもNotionへの読みは増えません）

ポイント表（記録の内容が濃いほど多くもらえます。**1日の満点はちょうど100pt**）:

| 行動 | ポイント |
|---|---|
| 睡眠 7時間以上 | 25pt（6時間台=15pt、5時間台=8pt） |
| 運動の記録 | 1件目15pt、2件目以降は1件ごとに+5pt（1日最大25pt） |
| 食事の記録（朝・昼・夕 各10pt） | 最大30pt |
| 体調を記録 | 5pt |
| メモを記録 | 5pt |
| 全部そろった日（パーフェクトデー） | +10pt |
| 週（月曜はじまり）の運動が5日以上 | +35pt |

1日の合計がそのままスコア（100点満点）になります。100点は運動を3件記録した
うえで全部そろえた日で、そこそこの高望みです。

レベルは累計ポイントの平方根カーブで上がり
（`Lv = 1 + floor(√(pt × 難易度倍率 / 44))`。難易度倍率は★1=0.8〜★5=1.7）、
節目で見た目が育ちます: Lv3でほっぺ → Lv5で王冠 → Lv7できらきら → Lv9で金のオーラ。
（この飾りは、どのキャラクターを選んでいても同じように付きます）
ごはんくんの頭の上には「ごはんくん Lv.○」のバッジが付いてまわります。
**キャラクターを触ると動きます**（タップのたびに12パターンから1つ、音付き）。
レベル・ポイント・次のレベルまでの残りは、⚙️ →「キャラクター設定」の
いちばん上に出ます（以前はタップで吹き出しを出していましたが、画面を覆って
せっかくの動きが見えないため、設定画面に移しました）。
レベルが上がった時は、金色のリングときらきらが飛び散る「LEVEL UP!」の
演出が入ります（前回見たレベルだけを端末に覚えておき、上がっていたら
演出を出します。ポイント自体はどこにも保存しません）。記録が2日以上途切れると眠そうになります（💤が出て歩みが
遅くなるだけで、レベルは下がりません）。

時計カードには、その日が何%進んだかのゲージと残り時間を出しています。
「今日の運動」カードは、その日すでに運動していれば目標の案内の代わりに
ねぎらいの言葉を出します。今日まだ運動していない日は、リングの中の炎が消えて
**雨雲から雨が降ります**（運動を記録すると火がつきます）。下の曜日の並びも、
運動した日は**赤い炎**・していない日は**青い雨つぶ**・まだ来ていない日は
薄いグレーの炎で表します（火と水で色を分けているので、ひと目で見分けられます）。

**運動**の内容欄は複数行に対応しています。ジムで何種目かやった時などは**1行に1つ**書くと、
1回の「記録する」でそのまとまりが**1件の記録**として保存されます（履歴でも行のまま表示されます。
育成のポイントは1行を1種目として数えます）。
複数行を書く入力欄は**改行して行が増えるたびに、その行数ぶん背が伸びます**
（運動・メモの内容欄、食事の品目欄、編集シートの内容欄・品目欄。10行ぶんで止まり、
そこから先は中でスクロールします）。体調の「内容」は保存の形式が1行のため、
1行の入力欄のままです。

記録を**編集・削除すると、今日ぶんの表示がその場で追いつきます**
（「今日の活動」のコメントは直した内容で書き直され、カレンダー・今日の運動・
育成のポイントも更新されます）。過去の日を直した時は、今日の活動のコメントには
関係がないので書き直しません。
さらに、**開いた時にも食い違いを見つけて自動で書き直します**。ふりかえりは
Notionに保存されるため、別の端末で直した場合やアプリの外（Notion側）で
直した場合には、保存済みの古い文がそのまま残ってしまいます。記録の最終編集
時刻とふりかえりの最終編集時刻を比べて、記録の方が新しければ書き直します
（書き直しは1回だけで、次からは保存済みのものをそのまま返します）。

「毎日の記録」では、記録は日付ごとにまとまって並びます。**日付の行の右端にある
鉛筆アイコンを押すと、その日だけが編集モードになり**、記録1件ずつに編集・削除の
アイコンが出ます（もう一度押すと戻ります）。ふだんは記録だけがすっきり並ぶよう、
1件ずつのアイコンは隠しています。編集モードは日ごとに独立していて、
編集や削除で一覧が作り直されても続きます。

### カロリー（概算）

**食事**を記録すると、品目からおおよその摂取カロリーをOpenAIに推定させて、
記録テキストに `白米（約230kcal）` の形で書き足します。

**運動**を記録すると、その内容からおおよその消費カロリーを推定して、
`腹筋マシン27キロ×3、バイク5キロ（約280kcal消費）` の形で書き足します。
消費カロリーは**体重60kg前後の成人**を想定した概算です（⚙️ →「からだの設定」の
体重は1日の目安カロリーの計算にだけ使い、消費カロリーの推定にはまだ使っていません）。

履歴画面では、1件ごとの値（`朝食 07:30・約520kcal` / `運動 08:30・約280kcal`）と、
その日の合計を日付の下の行に表示します
（`摂取 約1,120kcal　消費 約630kcal　目安 2,700kcal`）。
**今日の行には「1日の目安カロリー」も並びます。**
既定は成人男性の目安（2,700kcal／日本人の食事摂取基準2020年版・身体活動レベル
ふつう・30〜49歳）で、⚙️ →「からだの設定」で性別・年齢・身長・体重・活動量を
入れると、**その人に合わせた値**（基礎代謝 × 身体活動レベル）に変わります。
基礎代謝はMifflin-St Jeorの式で計算し、BMIも一緒に表示します。
入力した値はこの端末にだけ保存され、サーバーにもNotionにも送られません。

あくまで概算なので、外れていることもあります。推定はおまけの位置づけで、
`OPENAI_API_KEY` が未設定・レート制限に達している・推定に失敗した場合は、
カロリー無しでそのまま記録されます（記録自体が失敗することはありません）。
内容を編集して保存し直すと、カロリーも推定し直します。

#### 過去の記録にあとからカロリーを付ける

カロリー推定を入れる前に記録したぶんには、当然カロリーが付いていません。
その記録が残っている間は「毎日の記録」の見出しの下に
**「カロリーが付いていない記録 ○件に、まとめてカロリーを付ける」**
ボタンが出るので、押すとまとめて推定してNotionに書き足します
（全部に付いたらボタンは消えます）。

1回のリクエストでは12件までにとどめ、残りが無くなるまで画面側が繰り返します
（1件ごとにOpenAIとNotionへの通信が発生するため、まとめてやると時間切れになるため）。
Obsidianは日付ブロックごと書き換わるので、重複は発生しません。

「なんとなく体を動かした」のように内容から量が読み取れず、カロリーを推定
できない記録には `（kcal不明）` の印を書き込みます（画面には出しません）。
印を残さないと、その記録がいつまでも「カロリーが付いていない記録」として
数えられ続け、ボタンが消えなくなるためです。
あとで内容を編集して保存し直すと、印は消えて推定し直されます。

同じ日に同じ食事種別を2回記録すると、Notion側は見出しが2つ並びます。
以前はこの2つを1つの記録として読んでいたため、編集して保存し直すと
片方の見出しに全品目を書き戻すことになり、品目が増え続けていました。
今は見出しごとに別の記録として扱います。
増えてしまった記録は、同じボタンで繰り返しを1つにまとめて直せます。

## 他の人に使ってもらう場合

やり方は2つあります。どちらも、コードはそのままで **Renderにもう1つ別のWebサービスを
追加デプロイする**だけです（同じGitHubリポジトリ・同じブランチでOK）。

**A. Web版（おすすめ。相手がNotionを使っていなくてもよい）**
　相手はURLを開いてメールアドレスを入れるだけ。記録はこちらで用意したデータベース
　（Supabase）に保存されます。手順は [docs/SETUP-web.md](docs/SETUP-web.md)。

**B. 相手の自分のNotionに保存する（従来）**
1. Renderで新しいWeb Serviceを作成し、同じリポジトリを指定する
2. **`NOTION_TOKEN` と `NOTION_PAGE_ID` の環境変数は設定しない**（ここが重要）
3. できあがった別URLを、使ってほしい人に共有する。相手は画面右上の⚙️から自分のNotion連携情報を入れる

### セキュリティ

- 記録の内容（Notion由来のテキスト）は、画面に出す時に必ずHTMLエスケープしています
- 全ページにContent-Security-Policyを付けています。スクリプトはこのサイト由来の
  ものだけ、外部への通信（connect-src）もこのサイトだけに制限しているため、
  万一XSSが紛れ込んでもNotionトークンを外部へ送るのは困難です

環境変数が無い状態でアクセスすると、画面右上に⚙️アイコンが表示され、
初回アクセス時に「Notion連携の設定」画面が自動で開きます。使う人はそれぞれ、

1. 自分の[Notion integrationページ](https://www.notion.so/my-integrations)で
   integrationを作成し、シークレットトークンを取得する
2. 自分のNotion上に記録用のページを作り、そのページに作成したintegrationを
   コネクトする
3. トークンとページIDを設定画面に貼り付けて保存する

だけで、自分専用のNotionページに記録できるようになります。設定はその人の
ブラウザ（localStorage）だけに保存され、サーバーには一切送信・保存されません。

**⚠️ 注意：オーナー自身の既存URL（`NOTION_TOKEN`/`NOTION_PAGE_ID`が設定済みの
インスタンス）をそのまま他の人に共有しないこと。** 設定済みのURLでは、
訪問者が自分のNotionを設定するまでの間、環境変数（＝オーナー自身のNotion
ページ）にフォールバックしてしまうため、他の人の記録がオーナー個人の
Notionページに混ざってしまいます。他の人に使ってもらう時は、必ず環境変数を
設定していない別デプロイのURLを渡してください。

なお、Obsidianへの反映はサーバーのローカルファイルへの書き込みが前提のため、
この「他の人用」のクラウドデプロイでは（オーナー自身のクラウド版と同様に）
利用できません。Obsidianも使いたい人は、このリポジトリを自分のPCに
クローンし、`start.bat`でローカル起動した上で自分の`.env`に
`OBSIDIAN_FILE_PATH`を設定してください。

音声入力・「今日の活動」のコメント・カロリー推定で使うOpenAI APIキーは、
現状オーナー共有のものを使う設計です（使う人が増えるとオーナーのOpenAI利用料が
増える点に注意）。
悪用・誤爆による費用の暴走を防ぐため、OpenAIを使うAPIには
**IPごとに10分あたり20回**の簡易レート制限をかけています
（`server.js` の `openaiRateLimit`）。利用者が増えてきたら、この上限値の調整や、
各利用者に自分のOpenAIキーを設定してもらう方式への変更を検討してください。

天気を表示する地域は、設定画面で各自が指定できます（未指定なら大阪）。
日本の都道府県・県庁所在地は `lib/weather.js` の内蔵テーブルで解決し、
そこに無い地名はOpen-Meteoのジオコーディングに問い合わせます
（Open-Meteoのジオコーディングは日本語地名を検索できないため、この二段構えにしています）。

```bash
git add -A
git commit -m "変更内容"
git push
```

- GitHub: https://github.com/gdai-ux/aibou-techo （非公開リポジトリ）
- Render: https://dashboard.render.com （サービス名: aibou-techo）
- Renderの環境変数（NOTION_TOKEN, NOTION_PAGE_ID）はRenderダッシュボードの
  「Environment」タブで管理（`.env` はクラウドには含まれない）
- **Instance Type は必ず「Free」を選ぶこと**（デフォルトが有料の「Starter」になっていることがあるので注意）

## ローカル版の起動（Obsidianへの反映も必要な時）

1. `start.bat` をダブルクリックする
2. ウィンドウが2つ開きます
   - 1つ目：アプリ本体のサーバー（`node server.js`）
   - 2つ目：外出先アクセス用のトンネル（Cloudflare Quick Tunnel、任意）
3. 自宅WiFi内：`http://<PCのIPアドレス>:3800`

## Notion → Obsidian 同期（sync.js）

- PCにログインするたびに自動実行されます（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\aibou-techo-sync.bat`）
- 手動で今すぐ実行したい場合：

```bash
node sync.js
```

- ログは `sync.log` に記録されます
- 同期は「Notionにあってobsidianに無いもの」を追記するだけで、既存の内容を書き換えることはありません（完全一致の文字列で重複チェック）

## 設定ファイル（`.env`、ローカルのみ）

| 項目 | 内容 |
|---|---|
| `PORT` | サーバーのポート番号（既定 3800） |
| `OBSIDIAN_FILE_PATH` | 追記先のObsidianノートの絶対パス |
| `NOTION_TOKEN` | Notion integrationのシークレットトークン（既定値。未設定でも、各利用者が設定画面で入力すればその人専用の値が優先される） |
| `NOTION_PAGE_ID` | 追記先のNotionページID（同上） |
| `STORAGE` | `pg` にするとWeb版（自前DB・ログイン必須）。未設定ならNotionに保存する従来モード |
| `DATABASE_URL` | Web版のPostgres接続文字列（Supabaseの Session pooler URI） |
| `SUPABASE_URL` / `SUPABASE_ANON_KEY` | Web版のログイン画面がブラウザからSupabase Authを呼ぶための公開情報 |
| `SUPABASE_JWT_SECRET`（または `SUPABASE_JWKS_URL`） | Web版でログイントークンを検証する鍵 |
| `SUPABASE_SERVICE_ROLE_KEY` | （任意）アカウント削除の時に認証側の利用者も消すための鍵 |
| `AI_FREE_VOICE_LIMIT` / `AI_FREE_REVIEW_LIMIT` / `AI_FREE_CHAT_LIMIT` | （任意）Web版のAI無料枠。既定は 20/月・3/週・15/週 |

`.env` は個人の認証情報を含むため、Gitには含めていません（`.gitignore`済み）。
クラウド版（Render）には `OBSIDIAN_FILE_PATH` を設定しないことで、
Obsidianへの書き込みを自動的にスキップする仕組みになっています。
`NOTION_TOKEN`/`NOTION_PAGE_ID` を設定しないデプロイ（「他の人に使ってもらう場合」参照）では、
各利用者が画面右上の⚙️から自分のNotion連携情報を設定する運用になります。

## 既知の制約

- 外出先用のCloudflareトンネルURLはアカウント不要のQuick Tunnelのため、起動のたびに変わります
- Notionのブロック構成の都合上、同じ日に同じ食事種別（例：昼食）を
  複数回追記すると、Obsidian側は1つの「昼食」見出しの下にまとまりますが、
  Notion側は追記した回数分「昼食」見出しが並ぶことがあります
  （履歴画面でも、その回数分の記録として別々に表示されます）
- Render無料プランは長時間アクセスが無いとスリープし、次のアクセス時に
  数十秒〜1分ほど起動待ちが発生することがあります

## 保存形式：ページ本文とデータベース

記録の保存先には2つの形式があります。

- **ページ本文形式（従来）**: 日付の見出しの下にテキストで追記していく形式
- **データベース形式（推奨）**: 1記録=1行のNotionデータベース。プロパティ単位で
  構造化されているため、テキストのパースに起因するデータ破損
  （品目が増え続ける等の過去の不具合）が構造的に起きません

⚙️設定 →「データベース形式へ移行」で切り替えられます。押すと、ページ直下に
「life-log 記録データベース」が自動で作られ、過去の記録が数日ずつコピーされます
（記録の量によって数分。途中で失敗してももう一度押せば続きから再開します）。
**元のページ本文は消さず、バックアップとしてそのまま残します。**
データベースがあることを検出すると、以降の読み書きは自動でデータベースに
切り替わります。表示・編集・削除・カロリー整え・ふりかえりはどちらの形式でも
同じように動きます。

注意: データベース形式では、編集・削除のObsidianへの同期（Notion→Obsidianの
上書き同期）は行いません。新規の記録はこれまで通りObsidianにも直接追記されます。
